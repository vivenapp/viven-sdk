# 컨텐츠 설계 (한 번에 요청)

> 관련 문서: [페르소나 및 시나리오](01-personas-and-scenarios.md) | [비개발자 프롬프트 가이드](04-beginner-prompt-guide.md)

"주사위 게임 만들고 싶어", "미니게임 만들어줘"처럼 **한 번에** 요청했을 때, AI Agent가 바로 코드를 작성하지 않고 **컨텐츠 설계**를 먼저 안내하는 방법을 설명합니다. 이 흐름을 이해하면 막연한 요청을 해도 AI가 범위를 좁히고, 설계를 제시한 뒤 단계별로 구현을 도와줍니다.

---

## 1. 언제 이 흐름이 적용되나?

다음과 같은 **추상적·한 번에** 요청을 하면 이 설계 흐름이 적용됩니다.

| 요청 유형 | 예시 |
|-----------|------|
| "~만들고 싶어" | "주사위 게임 만들고 싶어", "가위바위보 게임 만들고 싶어" |
| "~설계해줘" | "미니게임 설계해줘", "4인 협동 게임 아키텍처 설계해줘" |
| "~해줘" (범위가 넓은 경우) | "총기 게임 만들어줘", "퀴즈 게임 만들어줘" |

반대로 **동작을 구체적으로** 요청하면 설계 단계 없이 바로 코드를 제시합니다.

- 예: "버튼 누르면 텍스트가 바뀌게 해줘" → 바로 Lua 코드 + Inspector 설정 안내

---

## 2. 전체 흐름 개요

한 번에 요청 시 AI Agent는 아래 **3단계**로 진행합니다.

```
1. 범위 파악 (Scope Clarification)
   → 사용자에게 짧은 확인 질문

2. 컨텐츠 설계 (Content Design)
   → 포함/제외, GameObject, 구현 순서 제시

3. 구현 단계 분해 및 안내
   → "1단계부터 할게요" 형태로 단계별 구현
```

---

## 3. 1단계: 범위 파악 (Scope Clarification)

AI가 바로 설계에 들어가기 전, **짧은 확인 질문**으로 범위를 좁힙니다.

### 3-1. 확인 항목 예시

| 확인 항목 | 예시 질문 |
|-----------|-----------|
| **플레이 방식** | "혼자 할 건가요, 아니면 여러 명이 함께 할 건가요?" |
| **핵심 동작** | "주사위를 손으로 던지나요, 버튼으로 굴리나요?" |
| **결과 표시** | "결과는 화면에만 보이나요, 다른 사람에게도 보여야 하나요?" |
| **규칙·제한** | "점수 합산이나 라운드 제한이 필요하신가요?" |

### 3-2. 답변에 따른 범위 결정

| 답변 | 결정되는 범위 |
|------|----------------|
| 혼자 / 여러 명 | **싱글플레이** vs **멀티플레이** (RPC, RoomProperty, SyncView 필요 여부) |
| 손으로 던지기 / 버튼 클릭 | **GrabbableModule + Rigidbody** vs **버튼 UI + Lua 로직** |
| 나에게만 / 모두에게 | **로컬 UI** vs **RPC·SyncView로 동기화** |

→ 이 단계에서 **포함할 기능**과 **제외할 기능**이 대략 정해집니다.

---

## 4. 2단계: 컨텐츠 설계 (Content Design)

범위가 정해지면 AI가 **설계 템플릿** 형태로 제시합니다.

### 4-1. 설계 템플릿 구조

```
[컨텐츠명] (예: 주사위 게임)

■ 포함할 것 (In Scope)
- [핵심 기능 1]
- [핵심 기능 2]
- [멀티플레이 시 필요한 것]

■ 제외할 것 (Out of Scope)
- [나중에 추가 가능한 것]
- [특수 규칙 등]

■ 필요한 GameObject / 컴포넌트
- [오브젝트명] (컴포넌트 목록)
- [컨트롤러 등]

■ 구현 순서
1. [1단계]
2. [2단계]
3. ...
```

### 4-2. 주사위 게임 설계 예시

```
[컨텐츠명] 주사위 게임

■ 포함할 것 (In Scope)
- 주사위 VObject (GrabbableModule, Rigidbody)
- 던지기 → 정지 시 눈 값 판정
- 결과 UI (TextMeshPro)
- 멀티플레이 시 RPC로 결과 브로드캐스트

■ 제외할 것 (Out of Scope)
- 점수 합산, 라운드 제한 (필요 시 나중에 추가)
- 복수 주사위, 특수 규칙

■ 필요한 GameObject / 컴포넌트
- DiceRoot (VObject, VivenLuaBehaviour, GrabbableModule, RigidbodyView)
- DiceGameController (VivenLuaBehaviour) — 결과 UI 갱신
- WorldSpaceCanvas — 결과 텍스트

■ 구현 순서 (다음 단계에서 이 순서대로 진행)
1. 주사위 VObject 뼈대 (GrabbableModule, Rigidbody)
2. 던지기 + 정지 시 눈 값 판정
3. 결과 UI
4. (멀티플레이) RPC로 결과 전송
```

### 4-3. 설계 확인 후 진행

설계가 마음에 들면 **"1단계 해줘"**, **"다음"**처럼 요청하면 됩니다.  
수정이 필요하면 **"멀티플레이는 빼고 싶어"**, **"점수 합산도 포함해줘"**처럼 말하면 AI가 설계를 조정합니다.

---

## 5. 3단계: 구현 단계 분해 및 안내

설계를 바탕으로 **구현 단계**를 나누고, 한 단계씩 진행합니다.

### 5-1. 단계별 요청·응답 예시

| 단계 | 사용자 요청 예시 | AI 응답 |
|------|------------------|---------|
| 1 | "1단계 해줘" / "다음" | "주사위 VObject 뼈대를 만들어줄게요. [Hierarchy 구조 + Lua 코드]" |
| 2 | "1단계 끝났어. 다음" | "던지기 후 눈 값 판정 로직을 추가할게요. [코드]" |
| 3 | "2단계 끝났어" | "결과 UI를 추가할게요. [코드]" |
| 4 | "3단계 끝났어" | "RPC로 결과 전송을 추가할게요. [코드]" |

### 5-2. 각 단계에서 AI가 하는 일

- **Hierarchy 구조** 제시 (GameObject, 컴포넌트 배치)
- **Lua 코드** 제시 (복사·붙여넣기 가능한 형태)
- **Inspector 설정** 안내
- **참조 문서** 안내 (예: GrabbableModule, RPC 가이드 링크)

### 5-3. 다음 단계로 넘어가는 방법

- "다음에 뭐 해?"
- "1단계 끝났어. 다음"
- "다음 단계 해줘"

→ AI가 구현 순서에 따라 다음 단계를 안내합니다.

## 6. 다른 컨텐츠 유형별 설계 포인트

### 6-1. 가위바위보·선택형 게임

| 확인 항목 | 질문 예시 |
|-----------|-----------|
| 플레이어 수 | "1:1인가요, 여러 명이 참여하나요?" |
| 선택 방식 | "버튼으로 선택하나요, 오브젝트를 잡아서 선택하나요?" |
| 결과 표시 | "승패만 보이나요, 점수도 표시하나요?" |

**설계 시 포함될 수 있는 것**: UI 버튼, VivenLuaBehaviour, RPC(멀티플레이), RoomProperty(턴·상태)

### 6-2. 총기·발사형 컨텐츠

| 확인 항목 | 질문 예시 |
|-----------|-----------|
| 총 잡기 방식 | "GrabbableModule로 잡나요?" |
| 발사 트리거 | "버튼 누르면 발사? 트리거 당기면 발사?" |
| 총알 동기화 | "총알이 다른 사람에게도 보여야 하나요?" |

**설계 시 포함될 수 있는 것**: GrabbableModule, Rigidbody, RPC, SyncView(총알)

### 6-3. 협동·미니게임

| 확인 항목 | 질문 예시 |
|-----------|-----------|
| 인원 | "몇 명이 참여하나요?" |
| Host 역할 | "한 명이 게임을 진행시키나요, 모두가 동등한가요?" |
| 상태 공유 | "점수, 턴, 라운드 등을 모두에게 보여야 하나요?" |

**설계 시 포함될 수 있는 것**: RoomProperty, RPC, Host 검증, CustomSyncView

## 7. Skill·문서 연동

이 설계 흐름은 **viven-sdk-content-design** Skill에 포함되어 있습니다.

| 항목 | 내용 |
|------|------|
| **Skill** | `viven-sdk-content-design` |
| **트리거** | "~만들고 싶어", "설계", "아키텍처" |
| **대상 페르소나** | P1(비개발자), P2(개발자), P3(컨텐츠 제작자) |
| **연동 Skill** | `viven-sdk-beginner-workflow` (단계별 진행), `viven-sdk-implementation-roadmap` (구현 순서) |

Agent가 "~만들고 싶어"를 감지하면 → `viven-sdk-content-design` 로드 → 범위 파악 → 설계 제시 → 단계별 구현 안내 순으로 진행합니다.
