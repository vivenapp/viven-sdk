# 비개발자용 프롬프트 가이드

> 관련 문서: [페르소나 및 시나리오](01-personas-and-scenarios.md) | [컨텐츠 설계 (한 번에 요청)](05-content-design-for-one-shot-requests.md)

Unity나 Lua를 처음 접하는 분을 위한 **작업 순서**와 **AI에게 요청할 때 쓰는 프롬프트 작성 방법**을 안내합니다. 이 가이드를 따라가면 **초급 → 중급 → 고급**으로 숙련도를 높일 수 있습니다.

---

## 1. 나는 어느 단계인가?

아래에서 자신에게 맞는 단계를 찾아보세요.

| 단계 | 나의 상황 | 다음에 할 일 |
|------|-----------|--------------|
| **초급** | Unity, Viven, Lua 모두 처음이다 | [2. 초급 학습 경로](#2-초급-학습-경로)부터 시작 |
| **중급** | Unity·C#은 해봤다. Viven·Lua는 처음이다 | [4. 중급 학습 경로](#4-중급-학습-경로)로 이동 |
| **고급** | Viven으로 여러 컨텐츠를 만들어봤다 | [5. 고급 학습 경로](#5-고급-학습-경로)로 이동 |

## 2. 초급 학습 경로

**목표**: 간단한 UI와 상호작용을 만들 수 있다.

### 2-1. 작업 순서 (전체 흐름)

| 단계 | 할 일 | AI에게 이렇게 요청해 보세요 |
|------|-------|----------------------------|
| **1. 준비** | Unity에서 Viven 맵 씬 열기, VObject/VMap 구분 이해 | "Viven에서 새 컨텐츠 만들려면 먼저 뭘 해야 해?" |
| **2. 뼈대 만들기** | 빈 GameObject + VivenLuaBehaviour 붙이기 | "버튼 하나랑 텍스트 하나 있는 UI 뼈대 만들어줘" |
| **3. 동작 연결** | 버튼 클릭 → Lua 함수 호출 | "버튼 누르면 텍스트가 '클릭됨'으로 바뀌게 해줘" |
| **4. 기능 확장** | 물체 잡기, 점수 표시 등 추가 | "오브젝트 잡으면 이펙트 나오게 해줘" |
| **5. 테스트·수정** | 실행 후 에러 발생 시 | "nil 이라고 뜨는데 뭐가 문제야?" + 에러 메시지 복사 |

각 단계를 끝낸 뒤에는 **"다음에 뭐 해?"**라고 물어보면 AI가 다음 단계를 안내해 줍니다.

### 2-2. 시나리오별 도전 순서 (초급)

[페르소나 및 시나리오](01-personas-and-scenarios.md)의 **페르소나 1** 시나리오를 아래 순서대로 시도해 보세요.

| 순서 | 시나리오 | 상황 | 시도해 볼 프롬프트 |
|------|----------|------|-------------------|
| 1 | **S1-6** | 준비·시작 | "Viven에서 새 컨텐츠 만들려면 먼저 뭘 해야 해?" |
| 2 | **S1-1** | 첫 컨텐츠 시작 | "Viven에서 버튼 누르면 텍스트가 바뀌는 간단한 UI 만들어줘" |
| 3 | **S1-7** | 다음 단계 진행 | "버튼 뼈대 만들었어. 다음에 뭐 해?" |
| 4 | **S1-2** | 물체 상호작용 | "오브젝트를 잡으면 이펙트 나오게 해줘" |
| 5 | **S1-8** | 오디오 피드백 | "버튼 누르면 소리 나오게 해줘" |
| 6 | **S1-9** | 앉기 상호작용 | "의자에 앉으면 화면이 바뀌게 해줘" |
| 7 | **S1-11** | 타이머·대기 | "10초 뒤에 텍스트 나오게 해줘" |
| 8 | **S1-5** | 추상적 요청 | "주사위 게임 만들고 싶어" |
| 9 | **S1-3** | 게임 루프 | "가위바위보 게임처럼 선택하고 결과 나오는 거 만들어줘" |
| 10 | **S1-4, S1-14** | 에러 대응 | "스크립트 실행이 안 돼, nil 이라고 뜨는데 뭐가 문제야?" |

### 2-3. 초급용 프롬프트 패턴

#### 패턴 A: "~하고 싶어" (추상적·한 번에 요청)

```
[만들고 싶은 것] 만들고 싶어.
```

**예시**: "주사위 게임 만들고 싶어", "미니게임 만들고 싶어", "가위바위보 게임 만들고 싶어"

**AI가 하는 일**: 바로 코드를 쓰기보다, 먼저 **범위 파악**과 **설계**를 안내합니다.  
예: "혼자 할 건가요, 여러 명이 할 건가요?" → 포함할 기능 정리 → 구현 순서 제시 → "1단계부터 할게요" 형태로 단계별 안내

#### 패턴 B: "~하면 ~되게 해줘" (동작 명시)

```
[조건] 하면 [결과] 되게 해줘.
```

**예시**: "버튼 누르면 텍스트가 바뀌게 해줘", "오브젝트를 잡으면 이펙트 나오게 해줘", "의자에 앉으면 화면이 바뀌게 해줘"

**AI가 하는 일**: Lua 코드와 Inspector 설정 방법을 바로 제시합니다.

#### 패턴 C: "~가 안 돼" (에러 대응)

```
[증상] 인데 뭐가 문제야?
[에러 메시지] 라고 뜨는데 고쳐줘.
```

**예시**: "스크립트 실행이 안 돼, nil 이라고 뜨는데 뭐가 문제야?", "attempt to call nil 이라고 뜨는데 뭐가 문제야?"

**팁**: 에러 메시지를 **그대로 복사해서** 붙여넣으면 AI가 원인을 더 정확히 찾아줍니다.

#### 패턴 D: "다음 단계 뭐야?" (순서 진행)

```
1단계 끝났어. 다음에 뭐 해?
```

**예시**: "버튼 뼈대 만들었어. 다음에 뭐 해?", "1단계 끝났어. 다음"

### 2-4. 초급을 마쳤다면

아래를 할 수 있다면 **중급**으로 넘어갈 준비가 된 것입니다.

- [ ] 버튼·텍스트 UI를 만들고, 클릭 시 동작을 연결했다
- [ ] 오브젝트를 잡을 때 이펙트나 소리를 넣었다
- [ ] nil 에러가 났을 때 AI에게 물어보고 해결했다
- [ ] "주사위 게임 만들고 싶어"처럼 막연한 요청을 하고, AI가 설계·단계를 안내하는 흐름을 경험했다

→ [4. 중급 학습 경로](#4-중급-학습-경로)로 이동

## 3. 활용 팁 (전 단계 공통)

### 단계별로 나눠 요청하기

처음에는 한 번에 많은 것을 요청하기보다, **한 단계씩** 요청하는 것이 좋습니다.

1. "버튼 하나랑 텍스트 하나 있는 UI 뼈대 만들어줘" → 뼈대 완성
2. "버튼 누르면 텍스트가 '클릭됨'으로 바뀌게 해줘" → 동작 연결
3. "다음에 뭐 해?" → 다음 단계 안내

### 에러가 났을 때

에러 메시지가 뜨면 **전체 메시지를 복사**해서 AI에게 붙여넣어 주세요.  
예: `attempt to call a nil value (global 'checkInject')` → 이 문장 전체를 복사해서 "이 에러 나오는데 고쳐줘"라고 요청하면 됩니다.

### 막연할 때

"주사위 게임 만들고 싶어"처럼 **막연한 요청**을 해도 괜찮습니다.  
AI가 "혼자 할 건가요? 여러 명이 할 건가요?"처럼 질문으로 범위를 좁혀 주고, 그다음 설계와 구현 순서를 안내합니다.

## 4. 중급 학습 경로

**목표**: 멀티플레이, 점수판, Viven API 예제를 활용할 수 있다.

**전제**: Unity·C# 경험이 있거나, [초급 학습 경로](#2-초급-학습-경로)를 마쳤다.

### 4-1. 시나리오별 도전 순서 (중급)

[페르소나 및 시나리오](01-personas-and-scenarios.md)의 **페르소나 2** 시나리오를 아래 순서대로 시도해 보세요.

| 순서 | 시나리오 | 상황 | 시도해 볼 프롬프트 |
|------|----------|------|-------------------|
| 1 | **S2-1** | 총기 구현 | "총을 잡아서 버튼 누르면 총알이 발사되게 만들어줘" |
| 2 | **S2-2** | UI 상태 표시 | "UI에 점수 현황판이 뜨도록 만들어줘. 플레이어별로 갱신되게" |
| 3 | **S2-3** | 멀티플레이 | "주사위를 던졌을 때 결과가 모든 플레이어에게 보이게 해줘" |
| 4 | **S2-4** | Viven 특화 학습 | "GrabbableModule의 onGrab에서 이펙트 재생하는 예제 코드 보여줘" |
| 5 | **S2-7** | SittableModule | "SittableModule로 의자 앉기 구현하는 예제 보여줘" |
| 6 | **S2-8** | 방 상태 표시 | "방에 들어온 사람 수를 UI에 표시하고 싶어. RoomProperty로 할 수 있어?" |
| 7 | **S2-11** | 입력 처리 | "PC VR 버튼 입력 받는 거 Lua로 어떻게 해?" |
| 8 | **S2-5** | 에러 대응 | "RPC 호출 시 함수를 찾을 수 없다고 나오는데, Lua 함수명 규칙이 뭐야?" |

### 4-2. 중급용 프롬프트 패턴

- **기능 단위 요청**: "~되게 만들어줘" + **조건을 구체적으로** (예: "플레이어별로 갱신되게")
- **예제 요청**: "~예제 코드 보여줘", "~구현하는 예제 보여줘"
- **API 질문**: "~API 사용법 알려줘", "~로 할 수 있어?"

### 4-3. 중급을 마쳤다면

아래를 할 수 있다면 **고급**으로 넘어갈 준비가 된 것입니다.

- [ ] GrabbableModule, SittableModule 예제를 보고 적용했다
- [ ] RPC나 RoomProperty로 여러 플레이어에게 결과를 보여줬다
- [ ] 점수판·방 인원 등 UI 상태를 갱신했다
- [ ] RPC 함수명 오류 등 에러를 AI에게 물어보고 해결했다

## 5. 고급 학습 경로

**목표**: CustomSyncView, Host 검증, 아키텍처 설계를 다룰 수 있다.

**전제**: Viven으로 여러 컨텐츠를 만들어봤고, GrabbableModule·RPC·SyncView 등 키워드를 알고 있다.

### 5-1. 시나리오별 도전 순서 (고급)

[페르소나 및 시나리오](01-personas-and-scenarios.md)의 **페르소나 3** 시나리오를 참고하세요.

| 순서 | 시나리오 | 상황 | 시도해 볼 프롬프트 |
|------|----------|------|-------------------|
| 1 | **S3-1** | 구체적 키워드 | "GrabbableModule의 onGrab 시 이펙트가 재생되도록 만들어줘" |
| 2 | **S3-2** | 네트워크 동기화 | "RPC를 사용해서 주사위를 던졌을 때 UI를 모두에게 갱신하도록 만들어줘" |
| 3 | **S3-3** | CustomSyncView | "CustomSyncView로 주사위 눈 값을 동기화하는 구조로 바꿔줘" |
| 4 | **S3-4** | 아키텍처 설계 | "4인 협동 미니게임 아키텍처 설계해줘. Host 검증, RPC 흐름 포함해서" |
| 5 | **S3-6** | RoomProperty | "RoomProperty로 게임 상태(라운드, 턴) 관리하는 패턴 알려줘" |
| 6 | **S3-8** | Host 검증 | "RPC에서 Host만 실행하도록 검증하는 방법 알려줘" |
| 7 | **S3-5** | 트러블슈팅 | "SyncView.IsMine이 false인데 receiveSyncUpdate가 호출 안 되는 이유가 뭐야?" |

### 5-2. 고급용 프롬프트 패턴

- **키워드 기반 요청**: GrabbableModule, RPC, CustomSyncView, RoomProperty 등 **Viven 키워드**를 포함
- **설계 요청**: "아키텍처 설계해줘", "~패턴 알려줘"
- **트러블슈팅**: "~가 호출 안 되는 이유가 뭐야?", "~할 때 주의할 점 뭐야?"
